# 数据清洗与审阅工作台

[English](README.md) · [完整英文案例](CASE_STUDY.md)

## 这个作品到底做了什么？

把一份格式不统一、含重复和冲突记录的联系人 CSV，处理成“可以继续审阅的干净数据”和“需要人工确认的问题清单”。重点不仅是删掉重复行，还要能回答：哪一行被保留、哪一行被排除、为什么，以及是否有行不明不白地消失。

适用场景是 CRM 数据迁移前的准备、名单整理或导入前检查。这里没有连接真实 CRM，也不会自动修改任何客户系统。

## 数据是什么、从哪里来？

全部由 demo.py 固定规则生成，不含真实姓名、邮箱或客户资料。六列分别是联系人编号、姓名、邮箱、国家、加入日期、订阅方案。

共 1,180 行：1,000 行基础记录、100 行重复副本、20 行与原编号冲突的新版本，以及 60 行错误记录。后者分成 20 行缺编号、20 行邮箱格式错误、20 行未知国家。姓名是 Demo Contact，邮箱使用 example.test。

## 怎么处理？

先统一 Unicode、空白、大小写和允许的国家别名，再检查每一列。按联系人编号分组：完全一致的标准化记录保留首行；同编号有冲突，或者组内出现无效记录，整组交给人工审阅。不猜测缺失值，不把姓名相似的人擅自合并。

例子：同一编号的两行订阅方案分别为 basic 和 pro，程序不能判断谁是真的，因此两行都留在问题清单。它不会为了让最终表格更“干净”而随便选一行。

## 得到了什么，怎么验证？

生成干净 CSV、逐行处理记录、保留原始值的 JSON，以及可筛选的 HTML 报告。另附 Excel 审阅快照，但当前 Python 命令本身不生成 Excel。

实际结果：980 行保留、100 行重复、100 行待审阅；合计仍为 1,180 行。待审阅中有 40 行属于 20 个冲突编号的双方，另有 60 行输入错误。17 项自动测试通过，包括行数守恒、规则处理、重复执行、输出保护和特殊文本转义。

这不等于“真实数据准确率 100%”。这里证明的是程序符合预先约定的规则；没有真实业务标注、独立测试集、速度对照或节约工时的测量。Excel 公式在生成工具中检查过，未在原生 Excel 中验证。

## 客户真正使用前还需要什么？

需要客户确认真实字段、编号规则、国家/方案取值以及冲突处理办法。先用获准的小样本验收，再处理全量数据；真实导入应另行授权并准备备份。程序不验证邮箱是否存在，不做模糊去重，不保证适合任意规模数据。

这是 AI 辅助开发的独立演示，不是已完成的付费客户项目。复现命令和证据文件见英文说明。
